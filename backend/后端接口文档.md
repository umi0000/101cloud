# 101cloud 后端接口文档

版本：v1。Go/Gin/GORM后端代码已实现；启动需显式迁移、管理员引导、TLS及已发布政策。真实Incus硬件联调与本地协议验收范围分开记录。

依据：[后端设计方案](后端设计方案.md)。本文定义浏览器调用的业务后端API，不是宿主机Agent API。没有NAT、端口映射、任意Incus透传或宿主机Shell接口。实现入口为cmd/backend；本轮仅在隔离本地数据库及协议环境验收，未部署远端服务器。

机器可读契约：[openapi.json](openapi.json)，OpenAPI 3.1，覆盖155个实际注册操作及核心请求类型。

## 1. 通用协议

### 1.1 地址、类型与时间

- 前缀 `/api/v1`；下文路径均相对此前缀，WebSocket也使用该前缀。
- 后端自身通过HTTP提供接口，默认127.0.0.1:8080，不配置SSL证书。浏览器入口采用同源origin（`CLOUD_ORIGIN`）：生产为HTTPS，由反向代理终结TLS并转发HTTP；本地开发可为 `http://` origin（如Vite开发服务器代理，`CLOUD_ORIGIN=http://localhost:5555`）。WebSocket需允许升级。JSON请求使用 `Content-Type: application/json`，UTF-8。Cookie名称与Secure属性只由CLOUD_ORIGIN的scheme决定，Origin检查不因内部HTTP而降级。
- 数值型数据库ID以十进制字符串传输，例如 `"123"`，避免JavaScript整数精度损失。GPU UUID和随机运维session_id是不透明标识，不作数字解析。
- 金额、费率、精确累计量使用十进制字符串；pt最多6位小数。容量bytes及累计纳秒等64位量使用十进制字符串；数量、百分比、时长使用JSON数值，遵循各字段范围。
- 时间为RFC3339，响应统一带 `+08:00`，保留最多6位小数。请求时间必须带时区，入库转UTC+8；Agent的UTC时间由后端转换。业务日期按已发布额度策略的IANA时区计算，不从浏览器时区推断。
- `null`表示未知或不适用，不能当作0。省略字段表示未提交；不支持的字段一律422，禁止静默接受 `billing_mode`、任意Incus配置等越权参数。
- PATCH只更新列出的可写字段；省略保持原值，null仅用于明确可清空字段。PUT替换该接口定义的完整配置对象。
- GET列表项目含revision时，客户端可构造 `If-Match: "rev-{revision}"`；GET详情的ETag为权威版本。已有资源缺少可用版本时先读取详情，不使用通配符绕过并发检查。
- 同一资源的列表项与详情使用同一表示：字段集合和类型一致。JSON配置/快照字段（如dns_servers、properties、config、config_snapshot、calculation_snapshot、validation_details）返回解码后的对象/数组，不返回JSON编码字符串；布尔字段为true/false，不返回1/0；所有revision均为十进制字符串（ETag格式仍为`"rev-{revision}"`）。
- 政策版本引用统一使用通用政策版本ID（`GET /admin/policies/{kind}/versions`返回的id，十进制字符串）。请求与响应中的pricing_version_id、gpu_price_version_id、policy_version_id、policy_versions映射值及`GET /catalog/gpu-options`项目id均为该ID；内部旧版本表行号不对外暴露。写入时ID不存在或kind不符返回422 validation_failed；未发布/未生效的约束沿用各接口原有422/409。
- 示例ID、额度、配置仅说明协议，非默认业务数据。

### 1.2 认证、权限与CSRF

使用服务端Session。Cookie名称及Secure属性由 `CLOUD_ORIGIN` 的scheme决定：

| CLOUD_ORIGIN | Session Cookie | CSRF上下文Cookie | Secure |
|---|---|---|---|
| `https://…` | `__Host-101cloud_session` | `__Host-101cloud_csrf` | 是 |
| `http://…`（仅本地开发） | `101cloud_session` | `101cloud_csrf` | 否 |

两种情况均为HttpOnly、Path=/、SameSite=Lax，不设Domain。浏览器在普通http下拒绝保存Secure及 `__Host-` Cookie，因此http origin使用无前缀名称；此时口令与Cookie明文传输，后端启动时记录警告。Cookie均为HttpOnly，前端不读取也不设置它们，只需同源请求时携带凭据。会话Token不出现在JSON或URL。

除CSRF初始化、登录、健康探针外均需登录。登录及其他修改请求要求 `X-CSRF-Token`，校验Origin；CSRF初始化绑定短期浏览器上下文，登录后轮换。所有管理员路径要求admin角色；普通路径仅允许访问本人资源，管理员访问其他用户资源使用管理路径。跨用户ID查询按404处理，防止枚举。

用户停用或会话撤销后拒绝新请求并终止所属运维连接。登录错误统一提示，进行速率限制：用户名或密码错误（含用户不存在、账号停用）以及 `POST /me/password` 的current_password错误均返回401 `invalid_credentials`，message不区分具体原因；`unauthenticated` 仅表示缺少、过期或已撤销的会话，前端据此跳转登录。`invalid_credentials` 不清除也不撤销当前会话。这里不开放公共注册，账号由管理员创建。

登录速率限制按客户端IP及账号分桶。客户端IP默认取TCP对端地址；仅当对端属于 `CLOUD_TRUSTED_PROXIES` 时才采用 `X-Forwarded-For`（从右向左跳过可信代理后的第一个地址），不读取X-Real-IP。

### 1.3 响应、分页与错误

成功对象：

```json
{"data":{"id":"123"},"request_id":"req-01"}
```

列表：

```json
{"data":{"items":[],"next_cursor":null},"request_id":"req-02"}
```

列表通用参数：`limit`默认20、范围1–100，`cursor`为不透明游标；默认按创建时间及ID倒序。只支持各接口列明的筛选，游标绑定原筛选条件，不接受任意SQL字段排序。不默认返回昂贵的总数。

错误：

```json
{"error":{"code":"gpu_capacity_unavailable","message":"没有符合要求的可分配GPU","details":{"retryable":true}},"request_id":"req-03"}
```

| HTTP | code示例 | 语义 |
|---|---|---|
| 400 | invalid_json / invalid_cursor | 协议或游标错误 |
| 401 | unauthenticated | 缺少会话、会话过期或已撤销，需重新登录 |
| 401 | invalid_credentials | 登录用户名/密码错误，或修改密码时current_password错误；不影响现有会话 |
| 403 | forbidden / csrf_failed | 权限或CSRF失败 |
| 404 | not_found | 不存在或无权获知资源 |
| 409 | instance_busy / invalid_state / idempotency_conflict | 变更冲突、状态不允许、幂等键内容不符 |
| 409 | credit_exhausted / quota_exceeded / gpu_capacity_unavailable / ip_capacity_unavailable | 业务准入失败 |
| 409 | gpu_in_use / observation_incomplete / configuration_conflict | 不能安全调整GPU |
| 409 | policy_not_configured / policy_changed | 政策未发布或确认的版本已变化 |
| 412 | revision_conflict | If-Match与当前版本不一致 |
| 422 | validation_failed / unsupported_configuration | 字段错误或配置不支持；details.fields给字段路径及原因 |
| 428 | precondition_required | 缺少必须的If-Match |
| 429 | rate_limited | 请求过密，附Retry-After |
| 503 | node_unavailable / metrics_unavailable | 节点或首次指标不可用 |
| 500 | internal_error | 返回request_id，不泄漏SQL、Token或堆栈 |

同步创建201、同步读取/修改200、无内容删除204、异步操作202。未知上游结果不映射为“已失败可直接重试”；已接受的任务通过任务状态表达unknown。

### 1.4 幂等、并发与异步操作

- 除登录、退出、CSRF外，所有POST及会产生外部操作的DELETE要求 `Idempotency-Key`（1–128个ASCII字符）。作用域为操作者、方法、规范化业务路径。
- 同键同规范化请求重放原结果，不重复创建、扣款或操作；同键不同请求409。任务和金融操作幂等记录不因短期缓存清理而失效。重复POST运维会话不另开会话，原会话已过期则返回原已过期结果。
- GET详情返回 `ETag: "rev-7"`。PATCH、PUT、DELETE及对已有资源的动作POST要求 `If-Match`，审批和发布同样适用；登录、报价、账户兑换及仅创建新资源的请求除外。服务端先识别已成功的幂等重放，再检查新动作的版本。
- 同实例变更串行；任务接受后业务版本立即前进。前端刷新资源后再发下一项操作。
- 异步202格式如下，Location指向任务详情：

```json
{"data":{"task_id":"800","instance_id":"123","status":"queued"},"request_id":"req-04"}
```

- 任务状态：`queued / running / waiting / unknown / succeeded / failed / cancelled`。成功必须以外部执行及状态核对为依据。
- 普通用户不提供任意任务重试/取消接口；停止实例、撤销申请等走明确业务操作。管理员只可请求核对，不可跳过事实把任务手改为成功。

| 方法与路径 | 请求 | 返回 |
|---|---|---|
| GET /auth/csrf | 无 | `csrf_token:string`，Cache-Control:no-store |
| POST /auth/login | `username:string,password:string` | user及新的csrf_token，设置Session Cookie；凭据错误401 invalid_credentials |
| POST /auth/logout | 无 | 204，撤销当前会话及其运维连接 |

| PATCH /me | 可选`email:string|null` | 更新后的User |

User：`id,username,email,role:user|admin,status:active|disabled|deleted,created_at`。用户名1–64字符，邮箱最多254字符；新密码12–128字符，不回显或记录日志。limits（`GET /me`与`GET/PUT /admin/users/{id}/limits`同一对象）为`id,user_id,revision:string,max_instances,max_resident_instances,max_vcpus,max_memory_bytes:string,max_disk_bytes:string,max_gpus`，缺失限制不解释为无限额度。

## 3. 产品目录与报价

| 方法与路径 | 筛选/请求 | 返回 |
|---|---|---|
| GET /catalog/zones | 通用分页 | 可用区id、code、name、availability |
| GET /catalog/plans | zone_id、instance_type | 可选规格列表 |
| GET /catalog/plans/{plan_id} | 无 | Plan及允许选配范围 |
| GET /catalog/images | zone_id、instance_type、architecture | Image：id、code、version、name、instance_type、architecture、fingerprint、gpu_ready:boolean、os_name、os_release、properties对象、status、revision、created_at、updated_at（与管理员镜像详情相同） |
| GET /catalog/gpu-options | zone_id | id为gpu-pricing政策版本ID（即套餐/报价policy_versions["gpu-pricing"]），model、access_mode、memory_mib、gpu_hourly_pt、availability；不泄漏其他租户信息 |
| GET /catalog/network-options | zone_id、instance_type | 允许的直连网络选项id及mode，不返回可任意占用的完整IP池 |
| POST /quotes | CreateElasticSpec | 价格明细、policy_versions、expires_at、admissible及阻止原因 |

Plan：`id,version,name,instance_type,resources,gpu,allowed_overrides,network_option_ids,image_ids,pricing_version_id`（pricing政策版本ID，与policy_versions.pricing一致；草稿未配置时为null）。列表与详情同一Plan对象。`instance_type=container|virtual-machine`；VM只提供CPU实例，gpu.count=0、gpu.model=null且不提供gpu_count选配。容器套餐的gpu{count,model,access_mode,max_hourly_pt}描述其唯一GPU规格：count为基准数量，可为0；gpu.model非null表示套餐提供GPU（count>0，或count=0且allowed_overrides.gpu_count.max≥1的可选GPU）。选配边界由目录返回，不由客户端任意输入突破。

报价不是预留或创建承诺。创建必须提交报价中确认的policy_versions；价格/策略变更返回policy_changed并要求重新确认。不会因用户访问目录或报价直接创建节点资源。

CreateElasticSpec：

| 字段 | 类型/约束 |
|---|---|
| name | string，1–128字符，用户显示名；Incus名字由后端生成 |
| zone_id,plan_id,image_id,network_option_id | 必填ID字符串 |
| resources | 必填对象：vcpus正整数、memory_bytes及disk_bytes正整数字符串；须在套餐允许范围内 |
| gpu | 必填对象：count非负整数、model字符串或null、access_mode=shared|exclusive、max_hourly_pt非负十进制字符串（最多6位小数）。count=0表示不使用GPU，任何套餐均允许，不受套餐基准数量或gpu_count.min限制：model必须为null，不与套餐型号/模式/价格上限比对，报价gpu_hourly_pt为0。count>0时套餐必须为提供GPU的容器套餐，count等于基准值或落在gpu_count的min/max/step内，model与access_mode等于套餐值，max_hourly_pt不超过套餐上限，镜像须gpu_ready，套餐须配置gpu-pricing；否则422（gpu-pricing缺失为409 policy_not_configured） |
| init_parameters | 非秘密JSON对象，遵循镜像/套餐指定的模板参数schema；禁止任意脚本、口令或私钥 |

CPU/内存/磁盘和GPU均以目录限制为准。用户不能指定node_id、gpu_uuid、IP、接口名、billing_mode、privileged或原生Incus配置。

## 4. 实例生命周期

| 方法与路径 | 请求/筛选 | 返回及行为 |
|---|---|---|
| GET /instances | product_type、observed_state、zone_id | 本人Instance分页 |
| POST /instances | CreateElasticSpec + policy_versions | 202；仅创建elastic、credit实例 |
| GET /instances/{id} | 无 | Instance及ETag |
| PATCH /instances/{id} | `name` | 200；仅修改显示名 |
| POST /instances/{id}/start | `{}` | 202；重新准入，核对额度、资源、实际GPU分配 |
| POST /instances/{id}/stop | `mode:graceful|force` | 202；force需明确权限及风险确认，保留磁盘 |
| POST /instances/{id}/restart | `mode:graceful|force` | 202；宽限期禁止借重启重新获得运行额度 |
| POST /instances/{id}/resize | `resources,policy_versions` | 202；仅套餐允许范围，默认停机修改；禁止磁盘缩容 |
| DELETE /instances/{id} | JSON：`confirm_name:string,delete_data:true` | 202；显式销毁实例和其数据，必须先停止；绝不由额度/空闲策略调用 |
| GET /instances/{id}/network | 无 | IP、prefix_length、gateway、DNS、mode、observed_at及quality |

force动作另需 `confirm_data_loss_risk:true`；未授权或未确认返回403/422。强停不删除卷但可能丢失未保存数据。不同配置的在线修改能力不能仅凭前端按钮推断，unsupported_configuration要求先停机。

Instance：

```json
{
  "id":"123","name":"training","product_type":"elastic","billing_mode":"credit",
  "instance_type":"container","zone_id":"1","plan_id":"10","image_id":"20",
  "resources":{"vcpus":6,"memory_bytes":"8589934592","disk_bytes":"96636764160"},
  "desired_state":"running","observed_state":"running","provisioning_state":"ready",
  "observed_at":"2026-10-29T15:00:00+08:00","state_stale":false,
  "active_task_id":null,"revision":"7",
  "credit_enforcement":{"status":"normal","event_id":null,"shutdown_deadline":null},
  "capabilities":{"start":false,"stop":true,"gpu_attach":true,"gpu_rebind":true,"console":true}
}
```

product_type：elastic或custom；custom的plan_id可为null，此能力需数据库迁移。desired_state为running/stopped/deleted；observed_state为unknown/pending/stopped/running/frozen/error/deleted；provisioning_state为pending/creating/initializing/ready/failed/deleting/deleted/unknown。

capabilities仅作UI提示，服务端每次重新授权。响应不含Agent地址、Token、Incus管理配置、初始化秘密。状态过期时明确state_stale，不能显示为确认已停止。

## 5. GPU申请、释放与换卡

| 方法与路径 | 请求 | 返回 |
|---|---|---|
| GET /instances/{id}/gpu-allocations | 无 | 分配id、uuid、model、status、gpu_hourly_pt、gpu_price_version_id（gpu-pricing政策版本ID）、configured/observed/release_verified（boolean或null）、revision、created_at、released_at |
| POST /instances/{id}/gpu-attachments | `count,model,access_mode,max_hourly_pt,allow_live` | 202；count是新增数量，选择合格候选最低负载卡 |
| POST /instances/{id}/gpu-detachments | `allocation_ids:string[],allow_live` | 202；只移除指定分配，不遗漏其他卡 |
| POST /instances/{id}/gpu-rebindings | `allocation_ids:string[],max_hourly_pt,allow_live` | 202；为指定旧分配选择新卡，不能传入目标UUID |

allow_live默认false；运行中必须显式true，但不是绕过占用检查的force。仅支持容器。手动移除/换卡也要求新鲜完整的空闲证据；GPU忙返回gpu_in_use，证据不足返回observation_incomplete。用户可先停止容器后调整，不开放杀GPU进程或整卡reset。

最低负载算法：先检查型号/能力、显存、健康、价格、共享/独占和预留名额，再按配置评分选择。默认SM利用率和显存占用率各50%；同分先取分配/预留少者，再按UUID排序。未知/过期指标不当0，无候选返回gpu_capacity_unavailable。并发绑定采用事务预留，不能依赖采样分数防超卖。

分配状态：reserved/attaching/active/releasing/unknown/released/failed/cancelled。配置移除不代表资源已回收；旧卡仍有占用时保留分配，返回release_verified=false。运行中换卡不迁移CUDA上下文，程序可能需要重新初始化GPU。持续自动均衡属于后台策略，不由浏览器定时调用重绑定接口实现。

## 6. 实例GPU自动策略

`GET /instances/{id}/gpu-policy` 返回配置、effective_policy、allowed_ranges、revision，以及idle_since、last_rebound_at、blocked_reasons。

`PUT /instances/{id}/gpu-policy` 完整替换下列用户配置，要求If-Match，返回200：

```json
{
  "idle":{"enabled":true,"timeout_seconds":1800,"action":"detach_gpu"},
  "rebalance":{"enabled":true,"allow_live":true,"max_hourly_pt":"5.000000"}
}
```

- timeout_seconds为正整数，范围由管理员配置；enabled=false仍保留已设置参数但不执行。
- idle.action=detach_gpu|stop_instance。公开动作detach_gpu映射内部release_gpu，不作为新增SQL枚举直接落库。
- 关机需全部已配置及实际观察到的旧GPU均满足空闲窗口；移除仅处理满足条件的卡。
- 占用进程/显存/设备引用不为零时不能仅靠低SM利用率判空闲；缺测、陈旧或代次变化重置连续窗口。
- 用户不能修改安全证据要求、平台阈值、冷却或强停权限。
- 自定义实例只能修改管理员授权部分；每日额度豁免不自动豁免用户主动开启的空闲策略。
- 自动均衡需源卡持续高负载、目标容器安全空闲、目标卡有足够改善且符合价格与冷却规则。已有额度关机事件时停止自动增配和换卡。
- 当前不开放自动恢复GPU开关：其触发规则尚未确认。用户通过gpu-attachments重新申请，不因期望配置残留而自动挂回。

## 7. 自定义实例申请与管理员下发

### 7.1 用户申请

| 方法与路径 | 请求/筛选 | 返回 |
|---|---|---|
| POST /custom-instance-requests | `name,reason,requested_config` | 201，申请记录，无实例创建 |
| GET /custom-instance-requests | status | 本人申请分页 |

## 10. Web终端与虚拟机控制台

| 方法与路径 | 请求 | 返回 |
|---|---|---|
| POST /instances/{id}/console-sessions | `kind:terminal|serial|vga`，terminal附cols/rows | 201，session_id、expires_at、websocket_path、protocol、status=preparing；轮询详情至ready再连接 |
| GET /console-sessions/{session_id} | 无 | 本人运维会话状态、expires_at及ETag，不返回上游秘密 |
| GET /console-sessions/{session_id}/stream | WebSocket Upgrade | 101，绑定当前登录会话、用户及实例 |
| DELETE /console-sessions/{session_id} | 无 | 204，关闭后端桥接与上游会话 |

容器使用terminal；VM按能力提供serial或vga。不接受任意宿主机命令、上游地址或operation ID。创建后连接票据保存在后端，URL只有不具备独立授权能力的随机会话ID；同源Cookie鉴权并校验Origin、资源权限和有效期，禁止把Agent Token放进URL。

会话仅允许一个活跃连接；过期/退出/撤销权限后关闭。重连重新创建会话，禁止无限复用过期票据。有效期和最大并发由平台设置，服务端返回expires_at。

当前预连接的上游流属于准备该会话的后端进程；单进程部署可直接使用，多进程部署必须为运维会话提供进程亲和性。返回console_process_mismatch时不能把票据转给其他进程盲重放，须创建新会话。普通API与持久化任务不因此变成内存业务状态。

terminal/serial子协议 `101cloud.terminal.v1`：

- 二进制帧：终端输入/输出原始字节。
- 客户端文本帧：`{"type":"resize","cols":120,"rows":30}`，cols/rows为1–1000整数；serial不支持resize时返回控制错误而不执行。
- 服务端文本帧：`{"type":"exit","exit_code":0}` 或 `{"type":"error","code":"console_closed","message":"会话已结束"}`。
- 禁止其他文本命令类型；退出后正常关闭1000，权限撤销1008，上游失败1011。限制帧长和缓冲，不能因慢客户端无限堆积输出。

vga使用 `101cloud.vnc.v1` 二进制RFB流，不混入终端JSON消息，适配noVNC等客户端。只审计连接与断开，不记录终端正文。此为拟定后端协议，不直接沿用Incus WebSocket secret协议。

模板参数schema必须封闭未知字段；初始化先验证已发布脚本SHA256，再通过原生exec执行并检查退出码。参数完整JSON通过INIT_PARAMETERS_JSON传入；环境变量安全的键另提供INIT_PARAM_<key>，其他键及含NUL值仅从JSON读取。不允许覆盖PATH等继承环境。cloud_init阶段会先等待cloud-init完成。

| gpu-idle | enabled、default_timeout_seconds、min_timeout_seconds、max_timeout_seconds、allowed_actions、gpu_utilization_threshold_pct、gpu_memory_threshold_pct、graceful_stop_timeout_seconds、allow_force_stop |
| metrics | raw_retention_days、rollup_retention_days、bucket_seconds、collection_interval_seconds；可选collection_timeout_seconds（1–120，默认30）、max_concurrent_nodes（1–32，默认4） |

时长为正整数；百分比0–100；权重非负且和为1；低阈值小于高阈值；默认值在min/max内。安全占用检查不可关闭。credit尚未确认的经济政策不得用隐含默认发布：grace_charge_mode=waived|accrue、restore_action=cancel_pending_stop|keep_deadline、storage_charge_mode=retained|running_only|free、offline_charge_mode=defer|continue，必须显式选择并由管理端展示含义；accrue需要独立待结算区间，不能使额度桶负余额。daily_validity_seconds表示有效期，不通过覆盖余额实现发放。

管理端gpu-idle.allowed_actions采用release_gpu/stop_instance，对应现有策略存储枚举；用户实例策略使用detach_gpu/stop_instance，后端在边界明确映射。信用和价格政策没有经济默认值，采集超时/并发默认仅为工程上限。CSRF上下文有效期30分钟，到期重新GET /auth/csrf；不需要退出会话。

政策作用域和引用由管理员在套餐、GPU、账号或平台配置中明确指定；已开始的额度宽限保留原deadline。平台credit绑定用于新建账户的默认值，既有账户不会被静默迁移；通过下述账户PATCH明确切换。新政策不能追溯改变历史发放、价格或正在执行的关机期限。

`GET /admin/platform-policy-bindings`返回平台各kind当前版本及ETag；`PUT /admin/platform-policy-bindings`提交各kind到已发布版本ID的完整映射，返回200。未配置必需政策时相关业务返回policy_not_configured，不使用示例值兜底。

兑换码生成的幂等重放只返回已生成记录ID和`codes_revealable:false`，不重新生成或长期保存明文；首次响应丢失时管理员禁用旧批次并用新幂等键生成。该秘密一次展示例外不改变“不得重复产生业务副作用”的幂等保证。code和初始密码禁止进入请求日志或幂等明文存档。

账户政策切换保留已发放额度和grant_cursor，不会在同一天重复发放；新的每日数量在后续业务周期应用。为避免把新的规则混进旧使用区间，存在活动资源会话时先明确停止/释放相应使用权；已建立的关机事件保持原策略快照。idle.allow_force_stop仅在管理员授权且重新验证持续GPU空闲后，允许正常关机失败时追加强停，不是关闭安全检查。

每日额度发放、后台结算、到期强停是内部调度任务，不提供普通用户“发放额度/执行计费”API。

## 14. 健康与前端调用顺序

`GET /health/live`返回200或503及status，不依赖节点在线；`GET /health/ready`只暴露服务是否具备处理请求的必要依赖，不泄漏数据库地址。外部可匿名访问但限制速率。节点离线不导致整个控制面退出就绪状态。

推荐调用顺序：

1. 获取CSRF → 登录 → 查询me与目录。
2. 用户选择规格 → quotes确认费用与政策版本 → instances创建 → 查询task到终态。
3. 列表和详情读取数据库/最新观测；界面按采样时间显示陈旧状态。
4. GPU新增/重绑定由后端选最低负载卡，前端不自行根据宿主负载挑UUID。
5. 周期查询credits/account和notifications；倒计时使用server_time校准，仅展示，后台独立执行截止任务。
6. 自定义申请提交后等待管理员批准；不先创建收费实例作为申请占位。
7. 终端先创建console-session再建立WebSocket，离开页面主动关闭。

## 15. 数据迁移与验收要求

原始37表通过sql/migrations/20261030_*.sql显式升级，补齐创建前申请、自定义无套餐关联、通知及额度截止事件、版本修订/幂等、实例策略、平台政策绑定、运维会话、节点管理与健康状态、套餐草稿和关联、未纳管导入。旧NAT表和配额通过空表保护迁移退役，不开放任何转发接口。

未确认的经济政策必须在启用计费前显式配置；API不暗中替用户决定收费口径。没有实现自动恢复GPU的业务规则时不发布相应开关。

接口验收至少包含：越权ID与字段注入、CSRF和WebSocket Origin、幂等重复与同键异参、过期ETag、并发资源预留、任务断电恢复和超时unknown、最低负载与未知指标、每日发放重复执行、600秒截止跨重启/额度恢复、自定义实例豁免、强停保留磁盘、多卡残留及换卡竞态、UTC到UTC+8转换、缺测不补零，以及没有NAT或任意节点代理入口。

文档示例不是测试替身。已在本地实际MySQL和HTTPS后端进程验证登录、幂等/版本冲突、政策发布、节点固定证书探测、直连网络、实例交付/未知任务恢复、最低负载选卡、管理员自定义豁免、持续指标及真实PTY WebSocket终端。节点端使用显式协议样本，不等同真实Incus/CUDA、多GPU热插拔或虚拟机VGA硬件验收；完整运行与验证记录见设计方案的实现说明。
